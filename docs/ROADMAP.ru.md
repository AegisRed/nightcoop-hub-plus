# Roadmap: NightCoop Hub Plus

Этот документ отделяет **то, что можно сделать в данном репозитории хаба**, от функций, для которых нужен исходный код **игрового NightCoop-мода**. Не стоит показывать «моды совместимы», пока обе стороны не передают проверяемую информацию.

## Что уже есть в Windows-ветке

- Самостоятельный Docker Compose без `network_mode`, с UDP 47800 и 47810–47824.
- One-click установщики хоста и гостя, управляемые правила Windows Firewall, UAC.
- Локальный read-only dashboard `127.0.0.1:47990`: отпечаток, адреса LAN/Radmin, строки для копирования, логи.
- GitHub Actions: PowerShell-парсинг, Compose config, проверка браузерного JavaScript и HTTP smoke test.
- README RU/EN, диагностика и сохранение signing key при обычном перезапуске.

## Проверка модов: что реально можно сделать

### Уже сейчас

В `src/ProtocolCore.hpp` есть версия игрового протокола `kVersion`. Когда гость присоединяется, `src/HubServer.cpp` сравнивает её с версией хоста и отправляет **`protocol mismatch`** при различии. Это помогает обнаруживать **несовместимые сборки NightCoop**, но **не** отсутствующие сторонние моды Cyberpunk.

HubPayload несёт игровые данные как непрозрачные зашифрованные пакеты. Сервер не читает содержимое игры. Это **правильное ограничение безопасности**, не баг.

### Промежуточный вариант без доступа к исходникам мода

Можно реализовать **внешний** локальный экспортёр на каждом ПК: он читает только известные папки Cyberpunk (`archive/pc/mod`, `mods`, `r6/scripts`, `red4ext/plugins`, папку CET-модов), записывает относительные имена и по возможности версии в JSON **без полных путей и персональных данных**. Затем в браузере сравнить два загруженных манифеста через File API **локально, без отправки на хаб**.

Это даст достоверные различия **по присутствию/названию/версии файлов**, но не докажет, что два мода конфликтуют на уровне скриптов или игрового состояния. Для крупных архивов лучше считать размер и метаданные, а не сканировать гигабайты SHA256 при каждом запуске. Такой инструмент можно сделать независимо от закрытого игрового DLL и поставить в P1.

Это **не автоматическое определение у каждого присоединившегося игрока**: каждый участник должен сам согласиться на экспорт. Учитывайте, что лицензия оригинального NightCoop-мода может запрещать модификацию его бинарного клиента без разрешения автора; внешний сканер избегает необходимости менять DLL.

### Для полноценной совместимости нужен протокол клиента

В игровом NightCoop-моде добавить *необязательный* этап перед входом в сессию:

1. Каждый клиент локально собирает **манифест**: версия Cyberpunk, сборка NightCoop, версии загрузчиков CET/RED4ext/REDmod (если доступны), список идентификаторов и версий сторонних модов с пометкой типа (косметика/квесты/механика/сетевая синхронизация).
2. **После защищённого handshake**, хост и гость обмениваются манифестами внутри существующего **E2E-шифрованного игрового канала**. Хаб их не получает в открытом виде и не хранит.
3. Клиенты нормализуют ID модов и сравнивают обязательные компоненты, версии и явно описанные зависимости.
4. Пользователь видит три уровня: **Block** (известная несовместимость NightCoop/критического компонента), **Warn** (потенциальная разница/нехватка gameplay-мода), **Info** (косметика или неизвестная совместимость).
5. Обязательно кнопки «показать отличия» и «копировать обезличенный отчёт». Если стороны не согласны передавать список, система должна работать как сейчас с предупреждением «проверка недоступна».

### Пример манифеста (проект, не существующий формат)

~~~json
{
  "schema": 1,
  "game_build": "example",
  "nightcoop_build": "example",
  "protocol": 128,
  "loaders": [
    {"id": "CET", "version": "example"},
    {"id": "RED4ext", "version": "example"}
  ],
  "mods": [
    {"id": "author.mod-id", "version": "1.2.3", "role": "gameplay", "multiplayer_required": false}
  ]
}
~~~

**Не стоит** автоматически блокировать всё, что различается: косметические моды, локальные настройки и любые неизвестные расширения могут без проблем сосуществовать. Даже полностью одинаковые списки **не гарантируют** отсутствие конфликтов (порядок загрузки, состояние сохранений, скрипты, настройки, чужие зависимости). Хеш одного архива не заменяет семантический ID и версию: разные сборки и необязательные патчи дадут ложные срабатывания.

Сначала достаточно «кто отсутствует / какая версия отличается». База **известных несовместимых пар** возможна позже, если есть воспроизводимые подтверждения. Не следует публично собирать полный список модов каждого игрока на центральном сервере без согласия.

### Можно ли показывать это в локальной веб-панели?

Да, **после** клиентской реализации и только с явной передачей добровольного, локального диагностического отчёта в панель, например через файл импорта. Подключение HubServer напрямую к приватным манифестам разрушит границу E2E и добавит риск утечки. MVP панели поэтому показывает лишь видимые серверу отказы и журналы Docker.

## План проверок перед выпуском

- Windows 10 и 11, чистая установка Docker Desktop и уже установленный Docker.
- Повторный запуск установщика: правила без дубликатов, signing key/fingerprint сохраняются, собственные Radmin IP не теряются.
- Guest без Docker: работает только локальная установка Firewall.
- Отдельно LAN и Radmin VPN, Windows-сеть Private/Public, несколько сетевых адаптеров.
- Шарды 1, 4 и 16: фактически опубликованы только нужные UDP-порты, redirect работает.
- Второй ПК получил неверный/правильный адрес; хаб не отвечает; неверный fingerprint; неверный код; несовпадение версии протокола.
- Dashboard слушает только 127.0.0.1, не доступен со второй машины и не открывает API для управления Docker.
- Логи не содержат закрытого ключа, а отчёты требуют ручной проверки приватных адресов перед пересылкой.
- Отказ UAC, отсутствие WinGet, нестабильное интернет-соединение, Docker Desktop просит перезагрузку.

## Что НЕ делать по умолчанию

- Не отключать Windows Firewall целиком.
- Не открывать UDP-порты на роутере через UPnP без отдельного выбора пользователя.
- Не вешать веб-панель на `0.0.0.0` / Radmin-IP без аутентификации, TLS и модели полномочий.
- Не обещать 100% работу через любой VPN или совпадение игрового контента.
- Не загружать `hub-sign.key`, полные логи или списки модов в публичные issue автоматически.
