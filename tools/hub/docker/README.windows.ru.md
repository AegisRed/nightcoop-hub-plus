# NightCoop для Windows: LAN и Radmin VPN

Простая настройка своего хаба на **Windows 10/11 + Docker Desktop**, без ручного редактирования Compose и ввода двух длинных команд Firewall. Скрипт работает **на текущем компьютере**. Игровые инвайты он **не создаёт и не меняет**.

## Быстрый старт — компьютер хоста

1. Скачайте репозиторий (кнопка **Code → Download ZIP**), распакуйте и откройте папку `tools\hub\docker`.
2. **Дважды нажмите `INSTALL-WINDOWS.cmd`**. Это установщик хоста: проверит Docker Desktop; если его нет, предложит установить через `winget` (с подтверждением лицензии). При первом запуске Docker может потребоваться WSL 2, согласие с условиями или перезагрузка — после этого просто запустите установщик ещё раз.
3. Подтвердите запрос Windows UAC для двух правил Firewall. Установщик запустит хаб, проверит локальную публикацию UDP 47800 и наличие отпечатка, затем покажет **цветную памятку** для игры. Инвайты он не создаёт.
4. В дальнейшем для логов, остановки и диагностики открывайте `START-WINDOWS.cmd` (меню), где можно также задать IP конкретных Radmin-пиров.

Если удобнее через PowerShell, команда однокнопочного режима:

   ~~~powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\nightcoop-windows.ps1 -Action install
   ~~~

**Важно:** однокнопочный запуск относится к **хосту**. Первоначальная установка Docker/WSL может требовать отдельного согласия и перезагрузки. Установщик проверяет только локальное состояние; он не может гарантировать доставку UDP на втором ПК.

Откройте в Cyberpunk меню мода → «Сервер» → «Добавить свой сервер». На машине хоста используйте **`127.0.0.1#ОТПЕЧАТОК`**. Если игра на другой машине, `127.0.0.1` не подходит: это всегда *тот* компьютер, где строку вводят.

Дальше создайте сессию обычным способом в игре. Кнопка «Копировать приглашение» сформирует действительный код — никакой отдельный генератор не нужен.

### На втором компьютере

Скопируйте/распакуйте тот же репозиторий. **Docker на госте не нужен**, если он не запускает собственный хаб. **Дважды нажмите `INSTALL-GUEST-WINDOWS.cmd`**, согласитесь с UAC — две настройки Firewall установятся без Docker. Для ручного выбора дополнительных IP Radmin используйте `START-WINDOWS.cmd` → пункт **2**. **Не запускайте `INSTALL-WINDOWS.cmd` на госте** — он предназначен для хоста.

Скрипт устанавливает правила **только на том компьютере, где запущен**. На обоих ПК требуется однократная настройка; повторный запуск обновляет только правила, созданные этим помощником, и не трогает другие правила пользователя. Если Radmin VPN использует другой профиль сети, второе правило работает с `-Profile Any`.

> На клиентском ПК эти два правила повторяют проверенную пользователем конфигурацию. Они сами по себе не гарантируют, что любые версии мода или сторонние антивирусы пропустят прямое P2P-соединение.

## Какой IP ставить в инвайт

**Нельзя просто отправлять `127.0.0.1` другому игроку.** Адрес — часть между `@` и `#`. Ключевой отпечаток (после `#`) и реальный код сессии (перед `@`) не трогайте.

| Где находится второй игрок | Что он должен вставить в игру |
| --- | --- |
| Сам хост на компьютере с хабом | Добавить сервер `127.0.0.1#MSAT-1F70-8QYY-MP1X` |
| В одной домашней сети LAN | `J3E5ZE@192.168.1.100#MSAT-1F70-8QYY-MP1X` |
| В одной виртуальной сети Radmin VPN | `J3E5ZE@26.42.1.7#MSAT-1F70-8QYY-MP1X` |

**Все IP, код и отпечаток в таблице — только пример.** Хост сообщает свой реальный LAN IP (обычно `192.168.x.x` или `10.x.x.x`) либо свой реальный **Radmin VPN IPv4** из приложения Radmin VPN. Хост и гость должны быть в одной сети Radmin. В консоли помощник показывает обнаруженные адреса и реальный отпечаток из журналов, если хаб уже запущен. При нескольких сетевых адаптерах внимательно выберите нужный IP.

Например, игра скопировала `J3E5ZE@192.168.1.100#MSAT-1F70-8QYY-MP1X`, но друг подключён через Radmin, а VPN-адрес хоста — `26.42.1.7`. Поменяйте **только адрес**: `J3E5ZE@26.42.1.7#MSAT-1F70-8QYY-MP1X`. Для гостей **не** используйте собственный Radmin IP гостя — нужен IP **хоста**.

## Что автоматически настраивается

В самостоятельном Windows-файле `docker-compose.windows.yml` **вообще нет `network_mode`** — Docker использует сеть по умолчанию. Публикуются только нужные UDP-порты:

~~~yaml
ports:
  - "47800:47800/udp"
  - "47810-47824:47810-47824/udp"
~~~

Это **самостоятельная конфигурация для Docker Desktop**, а обычный `docker-compose.yml` для Linux остаётся неизменным. Команда установщика:

~~~powershell
docker compose -f docker-compose.windows.yml up -d --build
~~~

Здесь по умолчанию **4 потока** (UDP 47800, 47810–47812), остальные порты зарезервированы под масштабирование до **16 потоков**. Если нужно, задайте `NIGHTCOOP_WINDOWS_SHARDS=1..16` в `.env` перед запуском. Выше 16 выставлять **нельзя**, потому что маршрутизируемые порты за пределами 47824 не опубликованы. Windows-профиль специально фиксирует базовый порт 47800.

Помощник ставит два входящих правила Windows Defender Firewall (через UAC, без отключения Firewall):

- **NightCoop Hub UDP (managed)**: UDP `47800,47810-47873`, профиль Private.
- **NightCoop LAN UDP (managed)**: UDP `47800,47810-47824`, адреса `LocalSubnet` и, если указаны, точные IP Radmin-пиров, профиль Any.

Эти правила повторяют конфигурацию из реального сценария: первая охватывает основной порт и возможные shard-порты, вторая — локальную сеть и Radmin. Для Radmin на обоих ПК можно ввести VPN IP **другой машины**, особенно если `LocalSubnet` или маршруты VPN настроены нестандартно. В настройках Radmin проверьте, что туннель подключён, а адреса доступны.

**Безопасность:** опубликованные Docker-порты по умолчанию привязаны ко всем интерфейсам. На некоторых конфигурациях Docker Desktop публикация портов может обходить обычные host firewall-фильтры. Используйте профиль для доверенного LAN/VPN, **не** включайте переадресацию этих UDP-портов на роутере в интернет без отдельной оценки риска. Адреса Radmin-пиров не являются механизмом аутентификации: подлинность хаба проверяется отпечатком.

## Если не работает

В меню помощника:

- **3** — показать IP, реальные примеры LAN/Radmin и отпечаток.
- **4** — смотреть живой журнал Docker (`Ctrl+C` для выхода).
- **5** — сохранить `nightcoop-diagnostics-ДАТА.txt` в текущую папку: версии/сеть, состояние двух правил, `docker compose ps` и последние 200 строк журнала. **Проверьте и скройте личные IP/данные сессий перед публикацией.**
- **6** — остановить контейнер. Ключ хаба остаётся в Docker-томе `nightcoop-hub-data`; его отпечаток не меняется.
- **7** — удалить только две созданные помощником Firewall-правила (запрос UAC).

Типичные причины:

| Симптом | Проверить |
| --- | --- |
| `127.0.0.1#...` работает только у хоста | Гость должен использовать LAN или Radmin **IP хоста**. |
| «Сервер не отвечает» | Запущен ли Docker, есть ли `47800/udp`, выполнен ли пункт 2 на другом ПК, доступен ли Radmin VPN. |
| Сессия создаётся медленно или не переводится на поток | `47810-47824/udp` и `NIGHTCOOP_WINDOWS_SHARDS <= 16`. |
| «Отпечаток не совпал» | Не копировать пример из README: использовать отпечаток **своего** хаба. Не удалять Docker-том с ключом. |
| LAN работает, а Radmin — нет | Используется **Radmin IP хоста**, вторая машина в том же Radmin VPN, правило для нужного удалённого IP и профиль Any. |
| UDP открыт, а игра всё равно не соединяется | Проверьте игровые версии, сторонний антивирус, блокирующие правила и журналы. UDP нельзя надёжно «пропинговать» обычным TCP-проверщиком. |

Если Docker Desktop не запущен, пункт 2 всё равно работает без Docker. Правила Firewall действуют только на локальной Windows. Подключение через Radmin VPN **возможно, но не гарантировано**: оно зависит от маршрутов VPN, настроек Docker Desktop и Windows Firewall. При работе Docker через bridge контейнер может видеть адреса через NAT, что отличается от нативного Linux `host`-режима и может влиять на прямой P2P; хаб способен ретранслировать трафик, когда прямой путь не открылся.

## Для Linux/VPS

Ничего менять не требуется: стандартный `docker-compose.yml` остаётся на `network_mode: host`; порт-мэппинг ему не нужен. Обычная инструкция — [README.ru.md](README.ru.md).
