# Свой хаб NightCoop

> **Windows 10/11, Docker Desktop, LAN или Radmin VPN?** Используйте отдельную
> [инструкцию для Windows](README.windows.ru.md) и `nightcoop-windows.ps1`.
> Она устанавливает два правила Firewall с разрешения администратора, включает
> UDP-проброс в Docker Desktop и показывает в консоли, какой адрес указывать в игре.
> Эта страница ниже предназначена в первую очередь для Linux/VPS.

*English version — [README.md](README.md).*

Игроки NightCoop находят друг друга через **хаб** — небольшой сервер: он выдаёт коды сессий, говорит каждому игроку, каким
адресом его видит интернет (так двое за домашними роутерами открывают прямой путь друг к другу), и пересылает игровой трафик,
когда прямой путь не открылся. Официальные хабы держит проект. Эта инструкция — как поднять **свой хаб**: для своей
компании, сообщества или региона, далёкого от официальных серверов.

Что хаб видит и чего не видит:

- Видит адреса игроков и сколько кто кому шлёт (иначе нельзя: он пересылает пакеты).
- **Не видит** саму игру: каждое звено «хост — гость» зашифровано из конца в конец (X25519, XChaCha20-Poly1305), хаб
  пересылает запечатанные конверты.
- У вашего хаба свой ключ. Игроки проверяют его по **отпечатку** — 16 знаков, которые вы даёте вместе с адресом. С отпечатком
  ваш хаб никто не подменит (перехваченное имя в DNS, враждебная сеть по дороге): игра откажется от сервера с другим ключом.

## 1. Что нужно

- Сервер на Linux с внешним адресом IPv4, подойдёт VPS. Хаб лёгкий: одно ядро держит около 300 игроков разом, когда примерно
  треть играет через хаб (остальные находят прямой путь и держат с хабом лишь тонкую связь); памяти хватит и 512 МБ.
- Открытые порты UDP: **47800** (входной) и **47810 … 47810+N−1** — по одному на поток хаба (N — ядра, отданные хабу). По
  умолчанию поток на ядро: на сервере с 4 ядрами это 47810–47813. Открыть 47810–47873 — хватит при любой настройке.
- Канал: около **0,5 Мбит/с в каждую сторону на игрока, который играет через хаб** (до ~1 Мбит/с в тяжёлом бою и в больших
  сессиях); игроки на прямом пути почти ничего не стоят. Лучше провайдер с безлимитным или щедрым трафиком.
- Docker Engine 24 или новее с Compose (`docker compose`). Без Docker — раздел 6.

## 2. Запуск в Docker

Из каталога исходников хаба (репозиторий NightCoop или архив исходников хаба — устроены одинаково):

```sh
cd tools/hub/docker
cp .env.example .env          # по желанию: порт, потоки, имя, регион
docker compose up -d --build
```

При первом запуске хаб создаёт свой ключ в томе `nightcoop-hub-data` и пишет отпечаток:

```sh
docker compose logs hub | grep fingerprint
# hub: the fingerprint of this hub's key is K3QF-9X2M-TV7A-0D4R — players of a private hub write its address as
# <name>#K3QF-9X2M-TV7A-0D4R …
```

Откройте порты в сетевом экране (пример для `ufw`; и в группе безопасности провайдера, если она есть):

```sh
sudo ufw allow 47800/udp
sudo ufw allow 47810:47873/udp
```

Разрешите хабу приёмный буфер побольше (он просит 4 МБ; без этого Linux даёт меньше и хаб пишет об этом в журнал):

```sh
echo 'net.core.rmem_max = 8388608' | sudo tee /etc/sysctl.d/90-nightcoop-hub.conf
sudo sysctl --system
```

Контейнер идёт от своего пользователя без прав, файловая система — только чтение; пишет он лишь свой ключ. Сеть — сеть
сервера (`network_mode: host`): хаб должен видеть настоящие адреса игроков, а NAT Docker стоил бы процессора на каждый пакет.

## 3. Что сказать игрокам

Дайте игрокам **адрес и отпечаток**, например `hub.example.org#K3QF-9X2M-TV7A-0D4R` (подойдёт и адрес числом:
`203.0.113.7#K3QF-9X2M-TV7A-0D4R`; другой порт — `hub.example.org:47900#K3QF-…`).

Хост добавляет сервер в игре: меню мода «Совместная игра» → **«Сервер: …»** → **«Добавить свой сервер»** → ввести (или
вставить Ctrl+V) адрес с отпечатком → «Сохранить». Сервер сразу выбран: «Создать сессию» идёт на него, справа сверху в меню
видно «СЕРВЕР: … · пинг · проверен». В сессии — пункт **«Копировать приглашение»**: строка вида
`ABC234@hub.example.org#K3QF-9X2M-TV7A-0D4R` (код сессии и сервер) — вставить напарнику в чат. Гость вставляет её в «Войти по
коду» (Ctrl+V или «Вставить код») — и попадает на тот же сервер; сервер запоминается у него в списке своих. Выбор и свои
серверы хранятся в `servers.txt` рядом с `NightCoop.dll`; вернуться на официальные — «Сервер: …» → «Авто: ближний».

Прежняя схема — файл **`hub.txt`** рядом с `NightCoop.dll` с одной строкой `hub.example.org#K3QF-9X2M-TV7A-0D4R` — тоже
работает: при первом запуске новой версии мод сам переносит его в «свои серверы» и выбирает (раз; файл остаётся, его можно
удалить). (С Cyber Engine Tweaks: `print(Game.NightCoopHostHub("hub.example.org#K3QF-9X2M-TV7A-0D4R", 47800))` и
`print(Game.NightCoopJoinHub("hub.example.org#K3QF-9X2M-TV7A-0D4R", 47800, "ABC234"))`.)

Что видят игроки, когда что-то не так:

| В игре | Почему | Что делать |
|---|---|---|
| «Сервер не прошёл проверку ключей», в окне сервера «ключ не совпал с отпечатком» | отпечаток не сходится с ключом сервера: опечатка, новый ключ на сервере или это вовсе не ваш сервер | проверить адрес («Сервер: …» → свой сервер → «Изменить адрес»); если ключ создан заново — дать игрокам новый отпечаток |
| «Сервер … не найден» | имя не находится в DNS | проверить запись DNS или писать адрес числом |
| «Сервер не отвечает» | закрыт UDP 47800 или хаб не запущен | сетевой экран, `docker compose ps`, `docker compose logs hub` |
| сессия создаётся на 5–6 секунд дольше обычного | закрыты порты потоков 47810+: хост ждёт порт потока и возвращается на входной (работает, но все сессии — на одном потоке) | открыть их (раздел 2) |

Без отпечатка (адрес только `hub.example.org`) игра тоже соединится и зашифрует связь, но не отличит ваш сервер от
подставного (в окне сервера — «шифруется, не проверен») — давайте отпечаток всегда.

## 4. Берегите ключ

Ключ — это лицо вашего хаба: `/data/hub-sign.key` в томе `nightcoop-hub-data`. **Сделайте копию** и держите её у себя:

```sh
docker run --rm -v nightcoop-hub-data:/data:ro -v "$PWD":/backup debian:13-slim cp /data/hub-sign.key /backup/
chmod 600 hub-sign.key
```

Ключ потерян или утёк: удалите том (или файл), перезапустите — хаб создаст новый ключ с **новым отпечатком**; дайте его
игрокам. Кто держит файл ключа, тот может выдать себя за ваш хаб.

## 5. Каждый день

- Журнал: `docker compose logs -f hub`. Пока на хабе есть игроки — раз в 5 минут строка `stats:` на каждый поток: сессии,
  соединения, пакеты и килобайты в секунду, `cpu N%` — доля одного ядра, которую занимает поток.
- Если `cpu` потока в ваши часы пик держится выше ~60 % — дайте хабу больше ядер (и `NIGHTCOOP_SHARDS`) или поднимите второй хаб
  для части игроков.
- Обновление: новые исходники, затем `docker compose up -d --build`. Сессии переживают перезапуск: хост каждой держит пропуск,
  подписанный ключом хаба, и за 90 с возвращает тот же код, гости входят по нему снова (ключ должен остаться прежним — том не
  удалять). Игроки на прямом пути тем временем играют дальше. Сборки мода старше этого хаба теряют сессии, которые идут
  **через** хаб, — поэтому перезапускайте, когда тихо. `--resume off` — без пропусков.
- Потоки: `NIGHTCOOP_SHARDS=auto` берёт все ядра сервера. Если контейнеру дано меньше ядер — задайте число сами. Каждый поток
  слушает свой порт (47810, 47811, …).
- Настройки — в `.env` (см. `.env.example`): порт, потоки, соединений на поток, имя и регион для журнала игроков и любые
  дополнительные ключи `nightcoop_hub`.

## 6. Без Docker

Хаб — одна небольшая программа на C++20. На Debian 13 / Ubuntu 24.04 или новее (g++ 13+):

```sh
sudo apt install g++ git
git clone https://github.com/lsalzman/enet.git /tmp/enet
git -C /tmp/enet checkout 5a9c537fd464b3c6d3c55e1d3bd47588faf71b42
mkdir -p obj
for f in callbacks compress host list packet peer protocol unix; do
  gcc -c -O2 -I/tmp/enet/include -DHAS_FCNTL=1 -DHAS_POLL=1 -DHAS_SOCKLEN_T=1 -DHAS_MSGHDR_FLAGS=1 -DHAS_GETADDRINFO=1 \
      -DHAS_GETNAMEINFO=1 -DHAS_INET_PTON=1 -DHAS_INET_NTOP=1 -DHAS_GETHOSTBYNAME_R=1 -DHAS_GETHOSTBYADDR_R=1 \
      /tmp/enet/$f.c -o obj/enet_$f.o
done
gcc -c -O2 vendor/monocypher/monocypher.c -o obj/monocypher.o
for f in src/Log.cpp src/NetCrypto.cpp src/HubServer.cpp tools/hub/main.cpp; do
  g++ -c -std=c++20 -O2 -I/tmp/enet/include "$f" -o "obj/$(basename "$f" .cpp).o"
done
g++ -o nightcoop_hub obj/*.o -pthread
```

Поставьте его и заведите ему своего пользователя (ключ живёт в его каталоге; при первом запуске хаб создаст его сам):

```sh
sudo install -m 755 nightcoop_hub /usr/local/bin/nightcoop_hub
sudo useradd --system --create-home --home-dir /var/lib/nightcoop --shell /usr/sbin/nologin nightcoop
sudo chmod 700 /var/lib/nightcoop
```

Служба systemd, `/etc/systemd/system/nightcoop-hub.service`:

```ini
[Unit]
Description=NightCoop hub
After=network-online.target
Wants=network-online.target

[Service]
User=nightcoop
ExecStart=/usr/local/bin/nightcoop_hub 47800 --shards auto --max-clients 512 --sign-key-auto /var/lib/nightcoop/hub-sign.key
Restart=always
NoNewPrivileges=true
ProtectSystem=strict
ReadWritePaths=/var/lib/nightcoop
ProtectHome=true
PrivateTmp=true
MemoryMax=1G

[Install]
WantedBy=multi-user.target
```

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now nightcoop-hub
journalctl -u nightcoop-hub | grep fingerprint
```

`sudo -u nightcoop nightcoop_hub --hub-public /var/lib/nightcoop/hub-sign.key` в любой момент печатает открытые ключи хаба и его
отпечаток.

## 7. Полезно знать

- Хаб держит много сессий разом (`--max-clients` соединений на поток, по одному на игрока); сессия (хост и до семи гостей)
  всегда живёт на одном хабе.
- Игроки на прямом пути пользуются хабом только для встречи: их игровой трафик через ваш сервер не идёт.
- Ваш хаб не входит в список официальных серверов и ничего не требует от проекта NightCoop: игроки выбирают его сами — в
  меню («Сервер: …» → «Добавить свой сервер») или приглашением хоста.
- На диске хаб хранит только свой ключ; коды сессий живут в памяти.
