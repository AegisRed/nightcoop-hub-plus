# NightCoop Hub Plus — свой хаб для Cyberpunk 2077

Форк хаба [NightCoop](https://nightcoop.net) с установкой для Windows в пару кликов, настройкой Firewall, поддержкой локальной сети и Radmin VPN, **локальной веб-панелью**, журналами и понятными подсказками для приглашений.

**[English README](README.md)** · [Подробная Windows-инструкция](tools/hub/docker/README.windows.ru.md) · [Linux/VPS](tools/hub/docker/README.ru.md) · [Идеи и ограничения](docs/ROADMAP.ru.md)

> В репозитории находится **только хаб**, не игровой NightCoop-мод. Мод должен быть установлен на компьютере каждого игрока. Хаб не сканирует чужие игровые файлы и не видит содержимое сквозного шифрования.

## Установка на Windows — хост

1. Скачайте ZIP тестовой ветки/релиза, распакуйте и откройте папку `tools\hub\docker`.
2. Дважды щёлкните **`INSTALL-WINDOWS.cmd`**.
3. Если Docker Desktop отсутствует, установщик предложит WinGet. Установка Docker требует вашего согласия и иногда дополнительной настройки WSL 2, виртуализации, принятия лицензии или перезагрузки.
4. Разрешите UAC создать **два правила Windows Defender Firewall**. Установщик запускает Docker, собирает хаб, проверяет публикацию UDP 47800 и наличие отпечатка.
5. Откроется локальная панель **http://127.0.0.1:47990**. Скопируйте из карточки «Для хоста» адрес вида `127.0.0.1#ВАШ-ОТПЕЧАТОК` и добавьте его в NightCoop: **Сервер → Добавить свой сервер**.
6. Создайте игровую сессию как обычно. **Код сессии даёт игра**, не установщик.

После перезагрузки Windows или первого запуска Docker установку можно повторить: ключ хаба хранится отдельно в Docker-томе и не теряется при обычном перезапуске.

Для управления позже запускайте **`START-WINDOWS.cmd`**: там запуск/остановка, правила Firewall, лог, экспорт диагностики, открытие/закрытие панели.

## На втором компьютере — гость

1. Установите сам NightCoop-мод для Cyberpunk 2077. **Docker гостю не нужен**.
2. Из распакованного репозитория запустите **`tools\hub\docker\INSTALL-GUEST-WINDOWS.cmd`**. Скрипт запросит UAC и создаст оба правила Firewall **на этом ПК**.
3. Если игроки не в одной домашней LAN-сети, подключите их к одной сети **Radmin VPN**.
4. Получите приглашение из игры у хоста и **замените только IP-адрес хаба** на LAN IPv4 или Radmin VPN IPv4 **хоста**. Код сессии и отпечаток после `#` оставьте.

Если Radmin VPN с нестандартными масками или маршрутами, в `START-WINDOWS.cmd` выберите **2** и укажите конкретные IPv4 других участников Radmin. Без удалённого доступа Windows не позволяет этому установщику менять Firewall на чужом ПК.

## Какие адреса писать

Синтаксис игрового инвайта:

~~~text
КОД_СЕССИИ@АДРЕС_ХОСТА#ОТПЕЧАТОК_ХАБА
~~~

| Кто подключается | Пример (все данные вымышлены) | Как выбрать IP |
| --- | --- | --- |
| Сам хост на ПК с Docker | `127.0.0.1#MSAT-1F70-8QYY-MP1X` | В игре добавить свой сервер |
| Друг в одной домашней сети | `J3E5ZE@192.168.1.100#MSAT-1F70-8QYY-MP1X` | LAN IPv4 **хоста** |
| Друг по Radmin VPN | `J3E5ZE@26.42.1.7#MSAT-1F70-8QYY-MP1X` | Radmin IPv4 **хоста** |

**Не отправляйте другу `127.0.0.1`!** На его ПК это адрес его собственного компьютера. Фингерпринт берите только из реального хаба, а код сессии — из игры.

## Веб-панель хоста

Адрес: **http://127.0.0.1:47990**. Запускается установщиком или пунктом **8** меню.

Панель показывает:

- **Состояние хаба:** запущен ли контейнер, опубликован ли UDP 47800, установлены ли два правила Firewall.
- **Отпечаток** ключа и готовую строку для собственного сервера `127.0.0.1#...`.
- **LAN и Radmin IP хоста**, редактируемые при наличии нескольких адаптеров.
- Кнопки «Скопировать сервер» и «Скопировать инвайт» для LAN/Radmin. Для полного инвайта нужно вставить **настоящий код**, скопированный из игры. Панель не создаёт код и не сохраняет его.
- **Последние 250 строк логов Docker**, фильтр вероятных ошибок/предупреждений, копирование текста.

Панель работает **только на loopback `127.0.0.1`**, не публикует отдельный порт в Docker и не предоставляет друзьям удалённое администрирование. Закрытый файл ключа она не читает. Пункт **9** меню останавливает панель, но **не сам хаб**.

**Важно про конфликты модов:** панель видит ошибки **хаба** (например, несовпадение версии протокола NightCoop или отказ во входе), но не список установленных игровых модов. Сетевой трафик между игроками зашифрован. Для поиска конфликтующих REDmod/CET/RED4ext/ArchiveXL/TweakXL нужна дополнительная функция на стороне **игрового клиента**; [план здесь](docs/ROADMAP.ru.md).

## Сеть, порты и Docker

| Порт | Для чего | Доступность |
| --- | --- | --- |
| UDP **47800** | Входной порт хаба | Клиенты LAN/Radmin |
| UDP **47810–47824** | Дополнительные потоки хаба, до 16 шардов всего | Клиенты LAN/Radmin |
| UDP **47810–47873** | Максимальный диапазон Linux-хаба на 64 шарда | Linux/VPS по необходимости |
| TCP **47990** | Локальная веб-панель | **Только 127.0.0.1** |

**Windows:** самостоятельный файл `docker-compose.windows.yml` **без `network_mode`**, только:

~~~yaml
ports:
  - "47800:47800/udp"
  - "47810-47824:47810-47824/udp"
~~~

Команда для ручного запуска:

~~~powershell
docker compose -f tools/hub/docker/docker-compose.windows.yml up -d --build
~~~

По умолчанию 4 шарда. Можно задать `NIGHTCOOP_WINDOWS_SHARDS=1..16` в `.env` (не больше 16, иначе часть UDP-портов не опубликована).

**Linux/VPS:** исходный `docker-compose.yml` по-прежнему использует `network_mode: host`; он не изменён. [Полная инструкция Linux](tools/hub/docker/README.ru.md).

**Правила Windows Firewall** (создаются с согласия администратора на *каждом ПК*):

1. **NightCoop Hub UDP:** UDP 47800,47810–47873, профиль Private.
2. **NightCoop LAN UDP:** UDP 47800,47810–47824, `LocalSubnet` и при необходимости точные Radmin IPv4 участников, профиль Any.

Повторная установка не удаляет существующие пользовательские правила. В меню **7** можно убрать только правила, созданные нашим помощником.

**Безопасность:** публикация Docker может работать на всех интерфейсах, иногда обходя часть правил Windows Firewall. Для домашней сети и Radmin не нужно открывать эти UDP-порты **на внешнем роутере в интернет**. Не публикуйте панель управления на `0.0.0.0`.

## Ошибки и диагностика

| Симптом | Что сделать |
| --- | --- |
| Docker не запускается | Проверить Docker Desktop, Linux containers, WSL 2, виртуализацию; принять условия и при необходимости перезагрузить |
| «Сервер не отвечает» | Проверить UDP 47800, работающий контейнер, Firewall **на обоих ПК**, VPN-адрес **хоста** |
| LAN работает, Radmin нет | Одна ли виртуальная сеть, верный ли Radmin IPv4 хоста; разрешить конкретный IPv4 другого игрока в правиле LAN |
| Создание сессии медленное | Проверить UDP 47810–47824 и число шардов 1–16 |
| Не совпадает отпечаток | Сравнить с реальным значением из журнала; не удалять том ключа |
| **Protocol mismatch** | Скорее всего, несовместимые сборки **самого NightCoop-мода** у хоста и гостя; обновить обе |
| Ошибка другого Cyberpunk-мода | Хаб сам её не диагностирует; нужны клиентские журналы и сравнение установленных модов |

Пункт меню **4** — живые логи, **5** — диагностика в текстовом файле. В отчёте могут быть локальные/VPN IP и сведения о сессиях — **проверьте и скройте их перед публикацией**.

Ключ хаба хранится в Docker-томе `nightcoop-hub-data`. Обычная остановка и перезапуск его не удаляют. Если удалить том, отпечаток поменяется, и всем придётся заново подтвердить сервер.

## Чего установщик не гарантирует

Проверяется локальная работа Docker, настройки Firewall, публикация UDP и отпечаток хаба. Но невозможно гарантировать маршрутизацию Radmin VPN на чужом ПК, блокировки стороннего антивируса, настройки роутера или совместимость игровых модов. Docker Desktop использует NAT, который может влиять на прямой P2P; хаб способен ретранслировать трафик.

## Состав проекта и дальнейшие идеи

- `tools/hub/main.cpp` — C++20 хаб.
- `src/HubServer.*`, `src/ProtocolCore.hpp` — сессии, сеть и причины отказов.
- `tools/hub/docker/docker-compose.windows.yml` — Windows Docker Desktop без host-network.
- `tools/hub/docker/INSTALL-WINDOWS.cmd`, `INSTALL-GUEST-WINDOWS.cmd` — установщики хоста и гостя.
- `tools/hub/docker/nightcoop-windows.ps1` — настройка и диагностика.
- `tools/hub/docker/dashboard.ps1`, `dashboard.html` — локальная веб-панель.
- `docs/ROADMAP.ru.md` — что ещё стоит сделать, особенно диагностика совместимости модов.

Репорты и PR приветствуются. Для сетевой ошибки приложите Windows/Docker версии, LAN или Radmin сценарий, шаги воспроизведения и **обезличенные** фрагменты логов. **Никогда не выкладывайте `hub-sign.key`.**
